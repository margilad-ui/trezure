## 3. עמוד 1: כמות לכל מיקום

### הסכמה
טבלה חדשה, הוספה בלבד:

```sql
create table if not exists public.item_locations (
  item_id uuid references public.items(id) on delete cascade,
  location_id uuid references public.locations(id) on delete cascade,
  workspace_id uuid not null references public.workspaces(id) on delete cascade,
  qty numeric not null default 0,
  updated_at timestamptz default now(),
  primary key (item_id, location_id)
);
```

**`items.location_id` ו `items.qty` נשארים ולא נמחקים.** הם הופכים ל"המיקום הראשי" ו"הסכום", ומתוחזקים בטריגר מתוך `item_locations`. כך כל המסכים הקיימים ממשיכים לעבוד ביום הראשון, וזו הסיבה שאפשר לעשות את המעבר הזה בלי לשבור כלום.

- טריגר על `item_locations` מעדכן `items.qty` לסכום, ו `items.location_id` למיקום עם הכמות הגדולה ביותר.
- מיגרציה: לכל פריט קיים נוצרת שורה אחת ב `item_locations` עם המיקום והכמות הנוכחיים.
- `adjust_qty` הקיים מקבל פרמטר מיקום אופציונלי; בלעדיו הוא פועל על המיקום הראשי.

### הממשק
- **דף הפריט:** במקום שורת כמות אחת, רשימה קצרה: נקודת צבע, שם המיקום, מונה עם פלוס ומינוס. מתחת: "סך הכל N". כפתור "הוסף מיקום".
- **חיפוש:** הצ'יפ של המיקום מסנן לפי `item_locations`, כך ש"מה יש במחסן" נכון גם לפריט שחלקו במשרד.
- **מסך מיקום:** מציג גם פריטים שחלקם כאן, עם הכמות המקומית ולא הכוללת.
- **הזזה** הופכת ל"העבר כמות ממיקום למיקום", עם ברירת מחדל של הכל.

## 4. עמוד 2: OKI מזהה פריט שכבר קיים

### שכבה 1: מסנן זול, רץ תמיד
רץ מיד אחרי ש `vision` מסיים, בתוך אותה פונקציה. מחזיר עד 5 מועמדים עם ציון:

| סימן | משקל | הערה |
|---|---|---|
| ברקוד זהה | ודאות מוחלטת | מדלג ישר להצעת איחוד |
| דמיון שם ומותג ב `pg_trgm` | גבוה | `similarity(name, ...) > 0.45`. עובד יפה בעברית כי הוא מבוסס שלשות אותיות ולא מילים |
| אותה קטגוריה ראשית | בינוני | |
| חפיפת תגיות | בינוני | ג'אקרד על מערך התגיות |
| אותם שדות מותאמים (צבע, חומר) | נמוך | |

דורש `create extension if not exists pg_trgm` ואינדקס GIN על `name` ועל `brand`.

### שכבה 2: OKI מסתכל על שתי התמונות
רצה **רק** כשהציון בתחום האפור (נניח 0.45 עד 0.8), ולא כשיש ברקוד זהה או ציון נמוך. פונקציה חדשה `compare`, שמקבלת שני `image_id` ושולחת ל Claude את שתי התמונות עם שאלה אחת: אותו מוצר, אותה משפחה, או לא קשור. מחזירה החלטה, ביטחון, ומשפט נימוק בעברית שנכתב בקול של OKI.

**עלות:** כ 2 עד 3 אגורות לקריאה, ורק על מועמדים אמיתיים. בצילום של 20 פריטים חדשים לגמרי, היא לא תרוץ אפילו פעם אחת.

### הממשק בסידור
שורה נוספת בכרטיס, מתחת לבועה של OKI, רק כשיש ממצא:

> **יש לך כבר מסגרת תמונה לבנה** · משרד · ארון 3 · 2 יחידות
> [ זה אותו דבר ] [ חדש אבל קרוב ] [ לא קשור ]

- **זה אותו דבר:** הפריט החדש נמחק, הכמות נוספת לפריט הקיים במיקום שנבחר בצילום (וזו בדיוק הסיבה שעמוד 1 קודם), והתמונה החדשה נוספת כזווית. פעולה אחת, הפיכה דרך "בטל".
- **חדש אבל קרוב:** נפתח פריט חדש והמיקום שלו נקבע למיקום של התאום. גם התגיות המשותפות מוצעות.
- **לא קשור:** נעלם ולא חוזר על הצמד הזה. נשמר ב `item_dismissed_matches` כדי שלא יציק שוב.

3. **ברקוד שונה = מוצר אחר** (D66), **וברקוד נקרא מהפריים בטלפון** (D67).

5. **שכבה 1 היא פונקציה במסד** ולא חלק מ `vision`, כדי שגם מסך הכפילויות ישתמש בה. **שכבה 2 בקריאה אחת לפריט** עם עד 3 מועמדים (D69).
6. **הסורק עלה למקום השני**, ונוספה סריקת תווית מקום בתוך מסך הצילום (D70).
7. **"שים ליד" כותב את קוד המקום** (D71), **איחוד רק ביחידה זהה** (D72), **מינימום לפריט כולו** (D73), **תווית לפריט** (D74), **ברקוד לא מוכר פותח צילום** (D75).
8. **מסך הכפילויות מפריד כפולים מדומים** (D76).
9. **הסף נקבע 0.42** על הנתונים האמיתיים: ששת האלבומים נוחתים בין 0.42 ל 0.54, ו OKI הכריע: אחד "אותו דבר" (אלבום ההידרנגאה צולם פעמיים), שלושה "דומים".
